โปรไฟล์บอร์ดคือแผนที่ที่เชื่อมหมายเลขขาที่เขียนในเฟิร์มแวร์เข้ากับขาจริงบนบอร์ด เข้าใจผิดตรงนี้
คือสาเหตุอันดับหนึ่งที่โค้ดดูถูกต้องแต่อ่านค่าอะไรไม่ได้เลย

## หมายเลข GPIO ไม่ใช่ตำแหน่งขาบนบอร์ด

ตัวอักษรที่พิมพ์บนบอร์ดมักไม่ใช่หมายเลข GPIO ที่คอมไพเลอร์ต้องการ ขา `D4` บนบอร์ด ESP32
ยี่ห้อหนึ่งคือ GPIO 4 แต่อีกยี่ห้อคือ GPIO 2 ให้เขียนหมายเลข GPIO เสมอ และตรวจกับโปรไฟล์ที่
แสดงในหน้าตั้งค่าโปรเจกต์

## ขาที่ดูว่างแต่ใช้ไม่ได้

บางขาดูเหมือนใช้ได้ แต่ถูกจองไว้แล้ว

| กลุ่มขา | เหตุผลที่ใช้ไม่ได้ |
| --- | --- |
| GPIO 6–11 | ต่อกับหน่วยความจำแฟลชภายใน ใช้แล้วบอร์ดรีสตาร์ตวนไม่หยุด |
| GPIO 34–39 | เป็นอินพุตอย่างเดียว ตั้ง `pinMode(..., OUTPUT)` ไม่ได้ และไม่มีตัวต้านทานพูลอัปในตัว |
| GPIO 0, 2, 15 | เป็นขากำหนดโหมดบูต ถ้า GPIO 0 ถูกดึงลงกราวด์ตอนรีเซ็ต บอร์ดจะเข้าโหมดอัปโหลดแทน |

## ADC2 ใช้ไม่ได้เมื่อเปิด Wi-Fi

ESP32 มีวงจรแปลงแอนะล็อกสองชุด ชุด ADC2 ถูกวงจร Wi-Fi ใช้อยู่ ดังนั้น `analogRead` บนขา
ของ ADC2 จะได้ค่าขยะหรือค้างไปเลยขณะที่ Wi-Fi เชื่อมต่ออยู่ ถ้าค่าที่อ่านถูกต้องก่อนเรียก
`WiFi.begin` แล้วเพี้ยนหลังจากนั้น ให้ย้ายเซนเซอร์ไปขาของ ADC1 คือ GPIO 32–39

## ตรวจรุ่นใน IoT Hub ก่อนนำโค้ดไปใช้

เปิด **เอกสาร → ข้อมูลอุปกรณ์** ค้นหารุ่นที่เลือกในโปรเจกต์ แล้วอ่านตารางขาเทียบกับวงจร
ข้อจำกัด ESP32 ในบทนี้ไม่ควรนำไปเหมารวมกับบอร์ดทุกรุ่นหรือ ESP32 ทุกตระกูล

หากต้องทดลองบอร์ดคนละรุ่น ให้สร้างโปรเจกต์ใหม่และเลือกบอร์ดที่ต้องการตั้งแต่ต้น
จากนั้นตรวจ `pinMode`, `digitalWrite` และ `analogRead` ทุกจุดก่อนย้ายโค้ด
การคัดลอกโค้ดไม่ปรับหมายเลขขาให้ตรงกับบอร์ดใหม่โดยอัตโนมัติ
