การอัปเดตผ่าน OTA คือการเขียนเฟิร์มแวร์ใหม่ผ่าน Wi-Fi แทนการต่อสาย USB นี่คือสิ่งที่ทำให้บอร์ด
ที่ติดอยู่บนเพดานหรือในตู้กลางแปลงยังดูแลต่อได้

บทนี้เป็นแนวทางสำหรับเฟิร์มแวร์บนบอร์ดจริง ต้องตั้งค่าเครื่องมืออัปโหลด OTA แยก
IoT Hub ยังไม่มีขั้นตอน OTA ครบวงจรจากปุ่ม Upload และตัวจำลองไม่ได้ยืนยันการอัปเดตผ่านเครือข่ายจริง

## บอร์ดต้องมีที่ว่างพอสำหรับเฟิร์มแวร์สองชุด

ตรวจว่าตารางพาร์ทิชันรองรับ OTA และอิมเมจใหม่มีขนาดไม่เกินพาร์ทิชันแอปปลายทาง
อย่าใช้เปอร์เซ็นต์แฟลชรวมเป็นเกณฑ์ตายตัว เพราะพื้นที่แอปและข้อมูลขึ้นกับ partition scheme
ที่เลือก อ่านตัวอย่างการแบ่งพื้นที่จาก [เอกสาร Partition Table ของ Espressif](https://docs.espressif.com/projects/arduino-esp32/en/latest/tutorials/partition_table.html)

## การตั้งค่าขั้นต่ำ

ตัวอย่างนี้แสดงเฉพาะส่วน OTA ต้องเพิ่มการนำเข้า `WiFi.h` และกำหนด `ssid`, `password`,
`otaPassword` รวมถึง `readSensors()` ในโปรเจกต์ก่อน จึงจะนำไปคอมไพล์ได้

```cpp
#include <ArduinoOTA.h>

void setup() {
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) delay(500);

  ArduinoOTA.setHostname("greenhouse-01");
  ArduinoOTA.setPassword(otaPassword);
  ArduinoOTA.begin();
}

void loop() {
  ArduinoOTA.handle();
  readSensors();
}
```

`ArduinoOTA.handle()` ต้องทำงานทุกรอบของ `loop()` ถ้าส่วนใดในลูปหยุดรอนานเกินหนึ่งถึงสอง
วินาที การจับมือเพื่ออัปเดตจะหมดเวลา และดูเหมือนว่าบอร์ดปฏิเสธการอัปโหลด

## ต้องตั้งรหัสผ่านเสมอ

ถ้าไม่เรียก `setPassword` ทุกอย่างในเครือข่ายสามารถเขียนเฟิร์มแวร์ทับบอร์ดของคุณได้ และไม่มี
ด่านที่สองมาช่วย พอร์ต OTA ที่ไม่มีการยืนยันตัวตนคือการเปิดให้รันโค้ดอะไรก็ได้บนอุปกรณ์นั้น

## ครั้งแรกยังต้องใช้สายอยู่ดี

บอร์ดจะรับการอัปเดตผ่าน OTA ได้ก็ต่อเมื่อเฟิร์มแวร์ที่รันอยู่มีส่วนจัดการ OTA อยู่แล้ว การเขียน
ครั้งแรกจึงต้องผ่านสาย USB เสมอ

## เตรียมทางถอยไว้ด้วย

ถ้าเฟิร์มแวร์ตัวใหม่พังใน `setup()` ก่อนถึง `ArduinoOTA.begin()` บอร์ดจะติดต่อผ่าน Wi-Fi ไม่ได้
อีกเลยและต้องเข้าไปถึงตัวเครื่อง ก่อนอัปเดตบอร์ดที่เข้าถึงยาก ให้ลองรันอิมเมจเดียวกันบนบอร์ด
ทดสอบและรีสตาร์ตดูสักสองสามครั้งก่อน
