เมื่อบอร์ดอ่านค่าเซนเซอร์ได้แล้ว ขั้นถัดไปคือให้แดชบอร์ดอ่านค่าจากบอร์ดได้ ปลายทาง JSON เล็ก ๆ
ผ่าน HTTP ก็เพียงพอ และใช้ได้กับไคลเอนต์ทุกแบบ

บทนี้เป็นตัวอย่างเฟิร์มแวร์สำหรับบอร์ดจริงในเครือข่ายของคุณ ตัวอย่างยังต้องเพิ่มการเชื่อมต่อ Wi-Fi
และฟังก์ชัน `readTemperature()` ก่อนคอมไพล์ ไม่ใช่ปลายทาง API ที่ IoT Hub สร้างให้แล้ว
และไม่ได้เชื่อม Dashboard Builder เข้ากับบอร์ดโดยอัตโนมัติ

## ส่ง JSON ไม่ใช่ HTML

ส่งค่าดิบที่เครื่องอ่านได้ แล้วปล่อยให้แดชบอร์ดจัดรูปแบบเอง และต้องระบุชนิดข้อมูลให้ชัด เพราะ
ไคลเอนต์ที่ต้องเดาเองมักเดาผิด

```cpp
#include <WebServer.h>

WebServer server(80);

void handleTelemetry() {
  char body[96];
  snprintf(body, sizeof(body),
           "{\"temperature\":%.2f,\"uptime\":%lu}",
           readTemperature(), millis() / 1000);
  server.send(200, "application/json", body);
}

void setup() {
  server.on("/telemetry", handleTelemetry);
  server.begin();
}

void loop() {
  server.handleClient();
}
```

การใช้ `snprintf` เขียนลงบัฟเฟอร์ขนาดคงที่ ช่วยเลี่ยงปัญหาหน่วยความจำแตกกระจายที่เกิดจาก
การต่อสตริงด้วย `String` ซ้ำ ๆ บนบอร์ดที่เปิดทิ้งไว้นาน

## ฟังก์ชันจัดการคำขอต้องสั้น

`handleClient()` ทำงานเฉพาะช่วงระหว่างรอบของ `loop()` เท่านั้น งานที่หยุดรอในฟังก์ชันจัดการ
คำขอ ไม่ว่าจะเป็นการอ่านเซนเซอร์ที่ช้า `delay` หรือลูปลองใหม่ จะทำให้คำขออื่นค้างทั้งหมด ให้อ่าน
เซนเซอร์ตามรอบของตัวเองใน `loop()` แล้วให้ฟังก์ชันจัดการคำขอคืนค่าล่าสุดที่เก็บไว้

## เบราว์เซอร์จะปฏิเสธคำตอบ

แดชบอร์ดที่เปิดจากคนละต้นทางจะอ่านเนื้อหาไม่ได้ ถ้าบอร์ดไม่อนุญาต

```cpp
server.sendHeader("Access-Control-Allow-Origin", "*");
```

การใช้ `*` ไม่มีปัญหาบนเครือข่ายภายในที่ไว้ใจได้ แต่ใช้ไม่ได้กับบอร์ดที่เข้าถึงได้จากอินเทอร์เน็ต
เพราะปลายทางที่เปิดโล่งบวกกับต้นทางแบบ `*` แปลว่าเว็บไหนก็ตามที่ผู้ใช้เปิดอยู่ อ่านค่าจากบอร์ด
คุณได้ทันที

## ปลายทางนี้ไม่มีการยืนยันตัวตน

ทุกอย่างในเครือข่ายเรียกได้หมด และ `WebServer` ใช้ HTTP ธรรมดา ค่าต่าง ๆ จึงวิ่งผ่านสายแบบ
ไม่เข้ารหัส ให้ถือว่าใช้ได้เฉพาะในเครือข่ายภายในเท่านั้น จนกว่าจะเพิ่มการตรวจสอบสิทธิ์และ TLS
