ผู้ช่วย AI ใน IDE ใช้ข้อมูลของโปรเจกต์เพื่ออธิบายโค้ด ตรวจวงจร และเสนอการเปลี่ยนแปลง
คุณควรอ่านข้อเสนอและตรวจผลหลังนำไปใช้ทุกครั้ง

## ก่อนถาม

1. เปิดโปรเจกต์ที่ต้องการและตรวจชื่อบอร์ด
2. บันทึกไฟล์ที่แก้ค้างไว้ให้สำเร็จ
3. เปิดไฟล์ที่เกี่ยวข้องใน IDE
4. เปิดแผงผู้ช่วย AI แล้วอ่านชื่อไฟล์ที่กำลังใช้งาน

## เขียนคำขอให้ตรวจผลได้

คำขอที่ดีมีเป้าหมาย อุปกรณ์ เงื่อนไข และสิ่งที่ต้องการให้คงไว้ เช่น:

> ช่วยตรวจวงจรและโค้ดของโปรเจกต์นี้ก่อนแก้ไข ต้องการให้กดปุ่มแล้วเปลี่ยนสถานะ LED
> ใช้บอร์ดเดิม เก็บส่วนพิมพ์ Serial ที่มีอยู่ และอธิบายว่าจะทดสอบอย่างไร

หากต้องการแค่คำอธิบาย ให้ระบุว่า “อธิบายก่อน ยังไม่ต้องเสนอการเปลี่ยนไฟล์”
ถ้าต้องการแก้ปัญหา ให้ใส่ข้อความผิดพลาดและขั้นตอนที่ทำให้เกิด แทนคำว่า “มันใช้ไม่ได้”

## งานที่เหมาะกับผู้ช่วย

| เป้าหมาย | ตัวอย่างคำขอ |
| --- | --- |
| เข้าใจโค้ด | อธิบาย setup และ loop ของไฟล์นี้ทีละช่วง |
| ตรวจวงจร | ตรวจไฟเลี้ยง กราวด์ และขาสัญญาณของอุปกรณ์ในโปรเจกต์ |
| เพิ่มความสามารถ | เพิ่มข้อความ Serial เมื่ออินพุตเปลี่ยน โดยเก็บพฤติกรรมเดิม |
| แก้ข้อผิดพลาด | อธิบายสาเหตุจากข้อความผิดพลาดนี้ แล้วเสนอการแก้เฉพาะจุด |
| วางแผนทดสอบ | เสนอขั้นตอนทดสอบปุ่มกด ทั้งก่อนกด ระหว่างกด และหลังปล่อย |

## อ่านแผนก่อนยอมรับ

เมื่อ AI เสนอแผน ให้ตรวจรายการในกล่องการเปลี่ยนแปลง:

1. **อุปกรณ์:** เพิ่มรุ่นและจำนวนที่ต้องการจริงหรือไม่
2. **สาย:** ขาต้นทางและปลายทางตรงกับงานหรือไม่
3. **ไฟล์:** แก้ไฟล์ที่ตั้งใจและคงโค้ดเดิมที่จำเป็นไว้หรือไม่
4. **คำเตือน:** มีข้อจำกัดหรือสายที่ยังต่อไม่สำเร็จหรือไม่

ข้อความตอบกลับไม่ได้แปลว่าโปรเจกต์ถูกแก้แล้ว ต้องยอมรับข้อเสนอเพื่อให้ระบบนำแผนไปใช้
ถ้าไม่ตรง ให้ปฏิเสธหรืออธิบายสิ่งที่ต้องเปลี่ยนก่อนขอใหม่

## หลังนำแผนไปใช้

1. รอผลการนำไปใช้สำเร็จ
2. เปิดไฟล์ที่เปลี่ยนและตรวจเนื้อหา
3. เปิด Virtual Device ตรวจอุปกรณ์และสาย
4. เริ่มจำลองและทำตามขั้นตอนทดสอบที่กำหนด
5. ถ้าผลผิด ให้ส่งอาการและข้อความผิดพลาดกลับไปอย่างเจาะจง

ถ้าแผนถูกปฏิเสธเพราะโปรเจกต์เปลี่ยนไปแล้ว ให้เปิดข้อมูลล่าสุดและขอแผนใหม่
หลีกเลี่ยงการแก้วงจรหรือไฟล์ในอีกแท็บระหว่างตรวจแผน

## เมื่อรอนานหรือเกิดข้อผิดพลาด

เวลาที่แสดงระหว่างรอคือเวลาที่ผ่านไป ไม่ใช่เปอร์เซ็นต์ความสำเร็จ
เมื่อคำขอหมดเวลาหรือล้มเหลว ให้ตรวจว่ายังไม่มีแผนที่ต้องยอมรับก่อนส่งใหม่
แบ่งงานใหญ่เป็นขั้น เช่น ตรวจวงจรก่อน แล้วจึงแก้โค้ด

ไม่ต้องใส่รหัสผ่าน Wi-Fi, API key หรือข้อมูลลับจริงในข้อความ
ใช้ชื่อแทนอย่าง `YOUR_SSID` หรืออธิบายว่าค่าเหล่านั้นจะถูกตั้งภายหลัง
