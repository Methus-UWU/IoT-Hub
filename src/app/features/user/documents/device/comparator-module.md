## ภาพรวม

เซนเซอร์หลายตัวในคลังนี้ใช้บอร์ดรูปแบบเดียวกัน คือตัวตรวจจับที่เปลี่ยนความต้านทานตามสิ่งที่วัด
ต่อเข้ากับวงจรเปรียบเทียบ LM393 บนบอร์ดสี่ขา ได้แก่ เซนเซอร์แสง LDR, ความชื้นในดิน FC-28,
แก๊ส MQ-2, เปลวไฟ, น้ำฝน และเสียง KY-038

เข้าใจบอร์ดแบบนี้ตัวเดียว ก็ใช้ได้ทั้งหมด

## ขาทั้งสี่

| ขา | หน้าที่ |
| --- | --- |
| `VCC` | ไฟเลี้ยง 3.3–5 V |
| `GND` | กราวด์ |
| `DO` | สัญญาณดิจิทัล เปลี่ยนสถานะเมื่อค่าข้ามเกณฑ์ที่ตั้งไว้ |
| `AO` | แรงดันแอนะล็อกตามค่าที่วัดได้จริง |

## `AO` ให้ข้อมูลมากกว่า `DO` เสมอ

`DO` บอกได้แค่ "เกินเกณฑ์หรือไม่" ส่วน `AO` ให้ค่าต่อเนื่อง ซึ่งเขียนเกณฑ์ในโค้ดได้เอง แก้ได้
ภายหลังโดยไม่ต้องหมุนตัวปรับด้วยมือ และบันทึกเป็นกราฟได้ งานส่วนใหญ่ควรใช้ `AO`

ข้อยกเว้นคืองานที่ต้องปลุกบอร์ดจากโหมดประหยัดไฟ ซึ่งต้องใช้สัญญาณดิจิทัลจาก `DO`

## ต่อ `AO` กับ ESP32 ต้องเลือกขาให้ถูก

ขา ADC2 ของ ESP32 ใช้ไม่ได้ขณะที่ Wi-Fi ทำงาน ให้ต่อ `AO` เข้าขา ADC1 เท่านั้น คือ
**GPIO 32, 33, 34, 35, 36, 39** ถ้าอ่านค่าได้ถูกต้องก่อนต่อ Wi-Fi แล้วเพี้ยนหลังจากนั้น
นี่คือสาเหตุ

บอร์ดที่จ่ายไฟ 5 V จะส่ง `AO` ออกมาสูงสุด 5 V ซึ่งเกินที่ขา ADC รับได้ ให้จ่ายไฟบอร์ดที่ 3.3 V
แทน หรือใช้ตัวแบ่งแรงดัน

## การปรับตัวต้านทานบนบอร์ด

หมุนช้า ๆ จนไฟ LED ดวงที่สองเพิ่งจะเปลี่ยนสถานะพอดีที่สภาพที่ต้องการตรวจ นั่นคือจุดเกณฑ์
ตัวปรับนี้มีผลกับ `DO` เท่านั้น ไม่มีผลกับค่าที่ออกทาง `AO`

## กรองค่าที่อ่านได้

ค่าจากขา `AO` มีสัญญาณรบกวนเสมอ อ่านหลายครั้งแล้วเฉลี่ยจะนิ่งขึ้นมาก

```cpp
int readAveraged(int pin, int samples = 16) {
  long total = 0;
  for (int i = 0; i < samples; i++) {
    total += analogRead(pin);
    delayMicroseconds(200);
  }
  return total / samples;
}
```

สำหรับค่าที่กระโดดเป็นครั้งคราว เช่น เซนเซอร์เสียง ค่ากลางกรองได้ดีกว่าค่าเฉลี่ย เพราะค่าผิดปกติ
หนึ่งค่าไม่ดึงผลลัพธ์ทั้งหมด

## ปัญหาที่พบบ่อย

- **`DO` เปลี่ยนสถานะถี่ ๆ ตรงจุดเกณฑ์** ต้องเพิ่มช่วงหน่วงในโค้ด คือใช้เกณฑ์ขาขึ้นกับขาลง
  ต่างกันเล็กน้อย
- **ค่า `AO` เต็มสเกลตลอด** จ่ายไฟบอร์ดที่ 5 V แล้วต่อเข้า ADC 3.3 V
- **ค่าเปลี่ยนตามอุณหภูมิห้อง** ปกติสำหรับบอร์ดราคาถูกกลุ่มนี้ งานที่ต้องการค่าสัมบูรณ์ต้องใช้
  เซนเซอร์ที่ปรับเทียบมาแล้ว
