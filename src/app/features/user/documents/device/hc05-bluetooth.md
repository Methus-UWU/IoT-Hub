## ภาพรวม

โมดูลบลูทูธ 2.0 ที่ทำตัวเป็นสายอนุกรมไร้สาย ข้อมูลที่ส่งเข้าขา `RX` จะออกไปที่อุปกรณ์ที่จับคู่ไว้
และข้อมูลที่รับมาจะออกที่ขา `TX` โค้ดฝั่งบอร์ดจึงเขียนเหมือนใช้พอร์ตอนุกรมธรรมดา

ESP32 มีบลูทูธในตัวอยู่แล้ว โมดูลนี้จึงมีประโยชน์กับบอร์ดตระกูล Arduino ที่ไม่มี

## ข้อมูลจำเพาะ

| หัวข้อ | ค่า |
| --- | --- |
| มาตรฐาน | Bluetooth 2.0 + EDR |
| แรงดันบอร์ด | 3.6–6 V |
| แรงดันขาสัญญาณ | 3.3 V |
| ความเร็วปริยาย | 9600 bps |
| ระยะ | ราว 10 เมตรในที่โล่ง |
| รหัสจับคู่ปริยาย | `1234` หรือ `0000` |

## ขา RX ทน 5 V ไม่ได้

แม้บอร์ดจะรับไฟเลี้ยง 5 V ได้ แต่ขาสัญญาณทำงานที่ 3.3 V การต่อขา `TX` ของ Arduino Uno
ซึ่งส่งออก 5 V เข้าขา `RX` ของโมดูลโดยตรงจะทำให้โมดูลเสียหายสะสม ต้องผ่านตัวแบ่งแรงดัน

```
Arduino TX ──[ 1 kΩ ]──┬── HC-05 RX
                       │
                    [ 2 kΩ ]
                       │
                      GND
```

ขา `TX` ของโมดูลต่อเข้าขา `RX` ของบอร์ดได้ตรง เพราะ 3.3 V ถือเป็นลอจิกสูงสำหรับบอร์ด 5 V

**สายต้องไขว้กัน** `TX` ของฝั่งหนึ่งไปเข้า `RX` ของอีกฝั่ง ต่อ TX เข้า TX คือความผิดพลาดที่
พบบ่อยที่สุด

## HC-05 กับ HC-06 ต่างกัน

- **HC-05** เป็นได้ทั้งฝั่งเรียกและฝั่งรับ มีปุ่มเล็ก ๆ บนบอร์ดสำหรับเข้าโหมดตั้งค่า
- **HC-06** เป็นฝั่งรับอย่างเดียว ไม่มีปุ่ม

งานทั่วไปที่ให้มือถือเชื่อมเข้าหาบอร์ดใช้ได้ทั้งคู่

## เข้าโหมดตั้งค่า

กดปุ่มบนโมดูลค้างไว้ขณะจ่ายไฟ ไฟ LED จะกะพริบช้าลงเหลือราวสองวินาทีต่อครั้ง แสดงว่าอยู่ใน
โหมดคำสั่ง โหมดนี้ใช้ความเร็ว **38400 bps** เสมอ ไม่ใช่ 9600

```
AT              ตรวจว่าตอบกลับ OK
AT+NAME=Greenhouse    ตั้งชื่อที่มือถือจะเห็น
AT+PSWD="4821"        เปลี่ยนรหัสจับคู่
AT+UART=115200,0,0    เปลี่ยนความเร็วตอนใช้งานปกติ
```

ทุกคำสั่งต้องลงท้ายด้วยทั้ง CR และ LF ตั้งค่าหน้าต่างพอร์ตอนุกรมเป็น "Both NL & CR"

## ตัวอย่างโค้ด

```cpp
#include <SoftwareSerial.h>

SoftwareSerial bluetooth(10, 11);   // RX, TX ของฝั่งบอร์ด

void setup() {
  bluetooth.begin(9600);
}

void loop() {
  if (bluetooth.available()) {
    char command = bluetooth.read();
    if (command == '1') digitalWrite(LED_BUILTIN, HIGH);
    if (command == '0') digitalWrite(LED_BUILTIN, LOW);
  }
}
```

ใช้ `SoftwareSerial` แทนพอร์ตหลัก จะได้ยังดูข้อความดีบักผ่าน USB ได้ แต่ `SoftwareSerial`
รับข้อมูลผิดพลาดที่ความเร็วเกิน 38400 bps

## ปัญหาที่พบบ่อย

- **จับคู่ได้แต่ไม่มีข้อมูล** สาย TX/RX ไม่ไขว้กัน
- **ได้ตัวอักษรขยะ** ความเร็วสองฝั่งไม่ตรงกัน
- **ไม่ตอบคำสั่ง AT** ยังไม่เข้าโหมดคำสั่ง หรือใช้ความเร็วผิด ต้องเป็น 38400
- **มือถือหาไม่เจอ** ไฟ LED ต้องกะพริบเร็ว ถ้ากะพริบช้าแปลว่าอยู่ในโหมดคำสั่ง
- **หลุดการเชื่อมต่อบ่อย** ไฟเลี้ยงไม่พอ โมดูลกินกระแสกระชากตอนส่ง
